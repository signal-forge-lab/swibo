Compact first. Detail on demand.

Swibo is organized around one expandable line per target. Runtime is the visible aggregate of the target lifecycle, Server and Tunnel move into the expanded diagnostic layer, and Monitor remains an independent lifecycle with its own controls in the collapsed row.

Confirmed interaction model

Collapsed: Target · Runtime status · Runtime Start/Stop + Restart · Monitor status · Monitor Start/Stop + Restart. Expanded: Server/Tunnel state · reason for DEGRADED · startup policy · last check · technical details · edit/options.

Operating principles

The UI follows the lifecycle model instead of presenting every check as an equal column.

01 / runtimeRuntime is the aggregate.

READY, DEGRADED, STARTING, STOPPING, STOPPED, and ERROR are the primary target states.

02 / checksServer and Tunnel explain Runtime.

They appear after expansion, not as permanent peer columns beside Runtime.

03 / monitorMonitor stays independent.

It has its own state and lifecycle controls and is never hidden inside the options menu.

04 / controlsOne primary lifecycle button.

The first control changes between Start and Stop. Restart stays beside it and is disabled when it has no useful meaning.

Lifecycle button rules

The same two-button pattern is used for Runtime and Monitor.

READY / DEGRADED

First button = Stop. Second button = Restart. Both are available unless an operation is already running.

STOPPED

First button = Start. Restart is disabled because Restart would only duplicate Start.

STARTING / STOPPING

Primary action shows operation-in-progress and is disabled. Restart is disabled until the transition resolves.

ERROR

Choose Start or Stop from the known runtime condition. Restart is available only when recovery semantics are valid.

UI rules

These rules should carry directly into the production Swibo implementation.

Use

  • One collapsed line per target as the default operating state.
  • Runtime as the visible aggregate; Server/Tunnel only in expanded diagnosis.
  • Runtime and Monitor each get state + Start/Stop + Restart in the same row.
  • Expand for startup policy, component detail, technical inspection, and edit options.
  • Hide absent Monitor/Tunnel controls instead of filling the row with N/A labels.
  • Keep icon controls keyboard accessible and expose descriptive tooltips / accessible names.

Avoid

  • Overall / Server / Tunnel / Monitor as four equal status columns.
  • Showing Start and Stop simultaneously when only one is currently valid.
  • Hiding Monitor lifecycle inside an overflow menu.
  • Turning every target into a tall card.
  • Requiring expansion just to perform normal Start/Stop operations.
  • Showing a generic options button in the collapsed row when its functions can live in the expanded section.
